# IDEF0 — МедДневник

Диаграмма верхнего уровня (контекстная) системы «МедДневник» для ведения личной медицинской истории.

## Контекстная диаграмма (A-0)

```
                    ┌─────────────────────────────────────────┐
  Учётные данные    │                                         │    Медицинские записи
  (email, пароль) ──┤                                         ├──► (приёмы, анализы,
                    │         A0: Вести медицинский          │     прививки, файлы)
  Профиль, ФИО,     │              дневник здоровья           │
  пол, дата рожд. ──┤              (МедДневник)              ├──► Отчёты / календарь
                    │                                         │     (события, графики)
  Справочники       │                                         │
  (врачи, анализы,  │                                         ├──► Уведомления на email
   прививки) ───────┤                                         │     (коды, 2FA)
                    └─────────────────────────────────────────┘
                              ▲
                              │
                    Администратор (справочники, пользователи)
```

| Стрелка | Тип | Описание |
|--------|-----|----------|
| Учётные данные | Вход | Регистрация, вход, 2FA, сброс пароля |
| Профиль | Вход | Имя, пол, дата рождения, настройки |
| Справочники | Вход | Глобальные и личные врачи, каталог анализов, панели, вакцины |
| Медицинские записи | Выход | Сохранённые данные в БД и файлы вложений |
| Календарь / отчёты | Выход | Агрегированное отображение для пользователя |
| Email | Выход | Коды подтверждения, 2FA, сброс пароля |
| Администратор | Управление | CRUD справочников, статистика, удаление пользователей |

```
                         ┌──────────────────────────────────────┐
                         │  A1: Управление доступом и профилем   │
                         │  (регистрация, вход, 2FA, профиль,    │
                         │   удаление аккаунта)                  │
                         └──────────────────────────────────────┘
                                        │
        ┌───────────────────────────────┼───────────────────────────────┐
        ▼                               ▼                               ▼
┌───────────────────┐         ┌───────────────────┐         ┌───────────────────┐
│ A2: Ведение       │         │ A3: Ведение       │         │ A4: Ведение       │
│ приёмов у врача   │         │ анализов          │         │ прививок          │
│ + вложения        │         │ + панели/пакеты   │         │ + вложения        │
└───────────────────┘         │ + вложения        │         └───────────────────┘
        │                     └───────────────────┘                 │
        │                               │                           │
        └───────────────────────────────┼───────────────────────────┘
                                        ▼
                         ┌──────────────────────────────────────┐
                         │  A5: Календарь и визуализация         │

                         └──────────────────────────────────────┘
                                        │
                                        ▼
                         ┌──────────────────────────────────────┐
                         │  A6: Администрирование (опционально)  │

                         └──────────────────────────────────────┘
```

## Детализация: загрузка файлов (черновик → запись)

```
  Файл с устройства
         │
         ▼
  ┌─────────────────────┐     draft_key (UUID)     ┌─────────────────────┐
  │ A7: Загрузить       │ ───────────────────────► │ Хранение вложения   │
  │ вложение (черновик) │                          │ (БД + uploads/)     │
  └─────────────────────┘                          └─────────────────────┘
         │                                                    │
         │  Сохранение записи (приём / анализ / панель)         │
         ▼                                                    ▼
  ┌─────────────────────┐                          Привязка к record_id
  │ A8: Создать запись  │ ───────────────────────► или batch_id (панель)
  └─────────────────────┘
```

## Детализация: вход с 2FA по email

```
  Email + пароль
         │
         ▼
  ┌─────────────────┐     неверно      ┌──────────────┐
  │ Проверить       │ ────────────────►│ Отказ        │
  │ учётные данные  │                  └──────────────┘
  └─────────────────┘
         │ OK, 2FA выкл.
         ├──────────────────────────────► JWT токен
         │
         │ OK, 2FA вкл.
         ▼
  ┌─────────────────┐
  │ Сгенерировать   │──► Email с кодом
  │ код, temp JWT   │
  └─────────────────┘
         │
         ▼
  ┌─────────────────┐
  │ Проверить код   │──► JWT токен
  └─────────────────┘
```

## Глоссарий IDEF0 для проекта

| Узел | Функция (глагол + существительное) |
|------|-------------------------------------|
| A0 | Вести медицинский дневник здоровья |
| A1 | Управлять доступом и профилем пользователя |
| A2 | Регистрировать приёмы у врача |
| A3 | Регистрировать результаты анализов (в т.ч. комплексами) |
| A4 | Регистрировать прививки |
| A5 | Отображать события в календаре и на графиках |
| A6 | Администрировать справочники и пользователей |
| A7 | Загружать файлы до сохранения записи |
| A8 | Привязывать файлы к сохранённой записи |

---

*Нотация IDEF0: прямоугольники — функции, стрелки слева/сверху — входы, справа/снизу — выходы, снизу — механизмы (Flask API, SQLite, React), сверху — управление (правила валидации, роли).*
